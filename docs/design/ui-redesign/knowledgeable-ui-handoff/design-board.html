One idea: the frontier

The product's core is the edge between what a learner knows and what they don't. The mark is a ring that isn't quite closed, with a highlighter dot where it stops. The same ring then does real work in the interface: it is the confidence indicator everywhere, so the brand and the data are one shape.

Palette and type

Prussian ink for identity and "known", a highlighter yellow for attention, graphite for unseen. The dark theme is a deep blue-slate instead of LibreChat's neutral grey, so the app is recognisable at a glance. Ratios are WCAG contrast against the theme's own background.

Why the layout changed

Dependencies have a direction, so the map uses it: foundations low, what you're working toward high. The old radial layout put Divisibility and Factor on opposite sides of Prime Number in an order that came from sorting IDs, which meant position carried no information.

Why the arrows show now

The old edges ran centre to centre, so each arrowhead sat under the node circle. Here edges stop at the pill's edge, and related (non-dependency) links are drawn dotted and only appear when a concept is selected.

Notebook and reading pane

The list rows look clickable because they are rows, with a ring, a name and a value. Selecting one opens a reading pane that floats above the chat instead of taking a slot in its layout. "Builds on" chips are real links, so a learner can walk down the prerequisite chain without going back to the list.

Building blocks that can't be broken into smaller whole-number factors.

Think back to divisibility: a number divides another if it splits evenly with nothing left over. Six breaks into 2 × 3, so 2 and 3 are factors of 6. A prime is the opposite, a stubborn number that refuses to split.

Picture seven tiles. You can't arrange them into a rectangle more than one row high, so 7 is prime.

Same vocabulary as chat

In tutor messages the existing badge states map onto the same system: known concepts get an ink dotted underline, weak ones get a highlighter mark (as above), new ones a faint ink wash. One visual language across chat, map and notebook.

Token starter

Values only. Upstream stores its colour roles as RGB channel triplets, so whoever implements this converts the hex and maps each role to the matching variable in client/src/style.css. Overriding these roles, rather than editing components, is what keeps the diff against upstream near zero.
